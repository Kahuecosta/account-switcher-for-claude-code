# Architecture

The extension sets `CLAUDE_CONFIG_DIR` (and per-account variables) for the window it runs in. Everything else (profiles, history, rules, limits, quota) helps decide **which** folder that is, or keeps the folders in a good state.

## Activation

`activationEvents` is `*` on purpose: the environment must be in place before the Claude Code extension (`onStartupFinished`, or earlier when its panel is restored) starts its CLI. `activate()` therefore does only synchronous work before applying the environment:

0. `perChat.init()` gives the window a new id (`CLAUDE_ACCOUNTS_WINDOW`) and its base profile (`CLAUDE_ACCOUNTS_BASE`) for the per-chat launcher.
1. `repo.detectRepos()` reads `.git` of each workspace folder (no `git` process).
2. `switching.startupAccount()` resolves the repository default or rule, or the remembered selection, from storage that is available synchronously (account identities are persisted for this reason).
3. `environment.applyEnv()` sets `process.env` of the extension host and the terminal environment collection.

Everything that waits (secrets, migrations, MCP mirroring, identities, watchers, prompts) runs afterwards in `afterActivation()`, which activation does not wait for. If the Claude Code extension was already active (a restored panel), its CLI may have started before or after the account was applied: `environment.markStartUncertain()` records that, and `environment.verifyStart()` settles it from the session the panel's CLI registers (`lib/sessions.js`; watched, with timed checks as a fallback). Until then any switch offers a reload. `switching.followSerially()` then tells the panel about the account without a reload when Claude Code supports that (see below), which settles it too.

## File-system safety

`profile.runOperation()` wraps every change to `~/.claude` or account folders:

- a lock file in the accounts root, so two windows never change folders at once;
- a progress notification that can be cancelled;
- a `Journal` (`lib/links.js`) that records each step; on failure or cancellation every step is undone in reverse order;
- files that would be deleted or rewritten are moved or copied to `~/.claude-accounts/.backups/<date>-<operation>/` with a `manifest.json` (the last 10 are kept).

Deleting an account folder removes its top-level links first and then moves it to the trash; without a trash, the user must confirm a permanent deletion.

## Storage

VS Code keeps `globalState` as one JSON object per extension; every write is echoed back to the extension host, which replaces the whole object, and the next write sends the whole object again. A late echo of an older write can therefore undo a newer write for good. The extension's state therefore lives in **one file per key** under `<globalStorage>/state/`, written atomically and read fresh (other windows write the same files) — see `src/state.js`.

| Key                                                                   | Content                                                                                                                |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `accounts`                                                            | `[{ id, dir, mode, kind }]`                                                                                            |
| `ratingPrompt`, `previousProcessWrapper`                              | rating prompt state; `claudeCode.claudeProcessWrapper` before per-chat accounts                                        |
| `accountMeta`                                                         | synced: `{ [id]: { name, color, icon, _t } }`                                                                          |
| `repoDefaults`                                                        | synced: `{ [repoKey]: { id, email, _t } }`                                                                             |
| `accountEnvironment`                                                  | `{ [id]: { NAME: { value } \| { secret: true } } }`; secret values in SecretStorage as `env:<id>:<NAME>`               |
| `accountIdentity`                                                     | last known `{ email, plan, organization, loggedIn }`                                                                   |
| `accountLimits`                                                       | `{ [id]: { at, until, kind } }`, shared by all windows                                                                 |
| `accountAvatars`, `mcpMirrored`, `dismissedNotices`, `importPrompted` | small local flags and maps                                                                                             |
| `resumeConversation` (workspace)                                      | `{ id, account, from?, at }`: conversation to reopen after the reload (30 min at most), copied again from `from` first |
| `selectedAccount`, `previousAccount`                                  | with `claudeAccounts.scope: user`; otherwise in workspaceState (not shared, so not echoed)                             |
| `schemaVersion`                                                       | storage version, see `src/migrations.js`                                                                               |

**Synced keys** (`accountMeta`, `repoDefaults`) are mirrored into `globalState` for Settings Sync. Every entry carries a timestamp (`_t`) and removals are kept as tombstones, so `state.pullSynced()` (at activation and when the window gets focus) merges both sides entry by entry with the newest entry winning; a mirror write lost to an echo is repaired by the next pull. On the first run of this storage, `state.init()` copies the `globalState` of earlier versions into the files.

## Switching without a reload

The Claude Code extension starts every `claude` process with the extension host's environment, read again at each start, and re-checks `CLAUDE_CONFIG_DIR` (account display, sign-in state, caches) whenever `claudeCode.environmentVariables` changes. `switching.followInPanel()` therefore applies the environment and calls `live.notify()`, which adds an entry to that setting and removes it right away; each window's Claude Code compares its own environment, so only the window that switched refreshes. `live.officialSupports()` first looks for the log message of that behavior in the installed Claude Code's code (its internal names change with every build). The state-changing part of every switch (the selection, the environment and telling Claude Code) runs one at a time (`switching.serially()`, also used by `syncFromStore()` and at startup), so the remembered selection, the environment and the panel always end on the account chosen last; messages stay outside, so a question waiting for an answer never holds up the next switch. `live.notify()` writes the entry and then takes it out of the value as it is at that moment, keeping any edit made meanwhile, and writes nothing if someone already took it out; `live.cleanup()` removes an entry left by an interrupted switch at the next start. Changes that only add or remove that entry are ignored by the extension's own configuration listener (`live.userVariables()`).

A conversation already open keeps its `claude` process, and two processes must never write the same conversation. So `handoff.continueInPanel()` copies the conversation with a new session id (`conversations.forkSession()`) and opens it in a new tab whenever the original may still be running: when switching without a reload, from a terminal, or with only the CLI. When the window reloads instead, every open conversation restarts, so the copy keeps its id (`conversations.copySession()`, which replaces a copy only with one that continues it and reports `diverged` otherwise, in which case a fork is made) and `handoff.resumePending()` reopens it after the reload, copying it again first. The conversation carried from the usage-limit notification is the one whose transcript reported the limit (`conversations.sessionOfFile()`, which also maps a subagent transcript to its conversation). `test/claude-code/` checks all of this against the real Claude Code extension (`npm run test:claude-code`, weekly in CI).
